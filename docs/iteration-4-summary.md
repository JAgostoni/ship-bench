## Assumptions made

1. **Footer row participates in arrow navigation.** §2.2A defines arrows over "options" and the footer's role separately; with wrapping arrows the active state can never return to none, so a keyboard-only user could otherwise never reach "See all" (Enter-with-none-active would be unreachable once an arrow key is pressed). The footer is therefore the last `role="option"` in the listbox — Enter on it goes to `/search?q=…`, same destination as Enter with none active.
2. **Dropdown gap and animation direction.** The spec gives no exact anchor offset; used 8 px below the input. "4px translate" is implemented as translateY(-4px) → 0 (the dropdown settles downward into place).
3. **The `/search` pre-fill does not fire a background dropdown request on page load** — requests fire only after the user interacts with the input (the spec ties requests to typing). The page's own server-side query already shows the results.
4. **Non-interactive rows (no matches / error) live outside the `listbox` element** (as siblings inside the dropdown surface) so the listbox only ever contains `role="option"` children; with zero options, `aria-activedescendant` is unset and arrows are inert, matching "non-interactive".
5. **S3 row title color:** the wireframe annotates "title 16px link"; rendered in `--color-accent` with underline on row hover (the row itself, not the title, is the link target — whole-row click per task 4.2).
6. **Count badge on S3** uses the `Badge` primitive per §4.7 ("article-count chip on S1/S3 headers"), wrapped in the `aria-live` node; the announced text includes an sr-only " for {q}" so the §7.4 example announcement ("3 results for deploy") is what screen readers hear.

## Issues encountered

- **New `react-hooks` v6 lint rules** (`set-state-in-effect`) reject synchronous `setState` inside effect bodies. The SearchBox was restructured: route-change reset (close + clear/pre-fill) is done by remounting the stateful inner component via a `key` derived from `pathname` + `q` instead of a sync effect; "closed below 2 chars" and the spinner are derived values (`dropdownOpen`, `loading`) rather than effect-set state. The spinner derivation (`pendingQuery === trimmed && data?.query !== trimmed`) also guarantees it can never get stuck after a dropped stale response.
- **Caught by the scripted pass:** retyping a query whose response was already cached (type → Esc → retype the same text) never reopened the dropdown, because the cached branch skips the fetch whose response is what normally opens it. Fixed by reopening from the `onChange` handler on a cache hit.
- WebKit's native clear (✕) button on `type="search"` inputs collides with the trailing kbd-hint/spinner slot and duplicates the Esc-clears affordance; hidden via `::-webkit-search-cancel-button` in `globals.css`.

## Decisions log

| # | Decision | Why |
| --- | --- | --- |
| 1 | Route-change behavior via remount `key` (outer `SearchBox` reads the URL, inner holds all state) | Implements "navigation closes + clears, `/search` pre-fills" declaratively, satisfies the new hooks lint, and guarantees no stale dropdown/in-flight state survives a navigation. Trade-off: the per-page result cache resets on navigation, which matches the spec's intent (the reopen-on-focus cache is a within-page affordance). |
| 2 | Stale guard checks both a sequence number and the live input value | The seq number alone misses "input changed but no new request fired" (e.g. backspace below 2 chars); the value check alone misses reordered in-flight responses for the same value. Both together cover every dismissal/refine path, with seq bumps on close/navigate so late responses can't reopen a dismissed dropdown. |
| 3 | `parseSnippet` is exported and unit-tested separately from the `Snippet` component | The splitting logic is the security-relevant part (whitelist semantics: only repo-injected tokens become elements); testing the pure function keeps the tests node-only — no jsdom needed. Component tests proper are iteration 5's scope. |
| 4 | `mark` styled as a global element rule, dropdown animation as a reusable `.pop-in` class, `--radius-xs: 4px` added as a token | Design §8.2 forbids hex/px outside `globals.css`; the highlight and the 150 ms animation are spec'd once and used by two+ surfaces (the dialog in iteration 5 reuses `.pop-in`). |
| 5 | `Input` extended (trailing slot + ref) instead of hand-rolling the search input | §4.3 defines SearchBox as a composite of the Input primitive; reusing it keeps §4.2 styling/error wiring in one place for iteration 5's forms. |
| 6 | Footer = last listbox option (see assumption 1) | Keyboard completeness beats a literal reading; mouse and screen-reader semantics are unchanged. |
