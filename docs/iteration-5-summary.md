## Assumptions made

1. **The page h1 is passed into the editor as a `heading` prop.** Task 5.3 puts the h1 in the RSC shell while design §1.3/S4 and §3.2 put it in the same sticky row as the editor's actions (client state). The shells keep ownership of the h1 markup (`<h1>New article</h1>` / `<h1>Edit article</h1>` as server-rendered nodes) and the editor lays it into the sticky heading row — both readings satisfied.
2. **Preview pane scroll offset.** §2.3's `max-height: calc(100vh - header - chrome)` is implemented as `calc(100vh - 240px)` (header 56px + sticky heading row + title field + labels/margins), in `globals.css`.
3. **Tab visuals.** The spec defines tab behavior (§7.3) but not appearance; implemented as calm underline tabs (2px accent bottom border + text color shift on the active tab, 44px tall touch targets), consistent with the accent-only-on-interactive rule.
4. **Bottom action DOM order is Save, Cancel.** Mobile requires "Save on top", so DOM order matches visual order there (§7.3 tab order = DOM = visual); on tablet the row is reversed via CSS so Save sits right per §3.2. The desktop heading row is Cancel→Save in both DOM and visual order per the wireframe.
5. **Counters measure raw (untrimmed) length** — what the user sees in the field — and use en-US thousands separators to match the "100,000" copy in the validation messages.
6. **Cancel is disabled while a save is in flight** (the spec is silent); it avoids navigating away mid-request, and the request is short-lived either way.
7. **Post-delete navigation does not focus the home h1** — task 5.4 specifies the push + refresh only; §7.5's h1-focus example is post-save, which is implemented.

## Issues encountered

- **Focusing the first invalid field can target a CSS-hidden textarea** (<1024px with the Preview tab active). `applyFieldErrors` switches to the Write tab and defers the `focus()` by a tick so it lands after React commits the visibility change.
- **A real-`disabled` confirm button drops DOM focus when the acting state starts** (the §4 note mandates real `disabled` for in-flight buttons). The dialog detects the orphaned focus and moves it to the (aria-disabled, still focusable) Cancel button, keeping the trap intact.
- **The textarea auto-grow measures 0 while hidden behind the Preview tab** (its `min-height` floors it); the measurement re-runs on tab switch as well as content change.
- **The editor's sticky heading row sits over `main`'s 24px top padding**; a negative top margin + equal padding extends its background so content doesn't peek through while scrolled (desktop only).
- **Scripted-pass selector collision (script-side only):** Next.js's route announcer is also `role="alert"`, so the banner assertion needed a text filter; and Playwright's `waitForURL("**/articles/*")` matches `/articles/new` itself, so the final check waits on the destination heading instead.

## Decisions log

| # | Decision | Why |
| --- | --- | --- |
| 1 | `ConfirmDialog` is fully controlled; the **caller** swaps `body` for the error state and owns busy/error flags | Keeps the primitive generic for its two §8.1 consumers (delete + discard guard, which never goes busy); the dialog adds `aria-live` on the body so the swap announces without re-render tricks. |
| 2 | Post-save h1 focus via a `sessionStorage` flag + `FocusHeading` on the detail page | The editor unmounts on `router.push`, so it can't focus the destination itself. The flag makes focus fire **only** after a save (regular browse visits keep default focus behavior), survives the RSC navigation, and degrades silently where storage is unavailable. |
| 3 | Editor actions are rendered twice (heading row ≥lg, below content <lg), hidden per breakpoint | §3.2 places them in two different DOM regions per breakpoint; CSS-hiding one copy (`display:none`, removed from the a11y tree) is simpler and more robust than portal/reparenting, mirroring the header's existing fallback-duplication pattern. |
| 4 | Per-field validation reuses `articleInput.shape.<field>` from the shared schema | Single source for rules **and** the §8.3-normative message strings — client blur errors, client submit errors, and server 400 `fieldErrors` are character-identical by construction. |
| 5 | Textarea auto-grow via a measure effect (`height = scrollHeight`) instead of CSS `field-sizing` | `field-sizing: content` still lacks cross-browser coverage; the effect is deterministic everywhere and keeps "page scrolls, no inner scrollbar" exact. |
| 6 | Once-errored fields tracked in a ref (`Set`), not state | Whether a field has ever errored only changes *future* validation behavior, never the current render — a ref avoids redundant re-renders and the hooks-lint pitfalls iteration 4 hit. |
| 7 | New tokens (`--color-backdrop`, `--container-dialog`) + `.editor-preview` rule added to `globals.css` rather than inline arbitrary values | Design §8.2 forbids hex/px outside `globals.css`; follows the iteration-4 precedent (`--radius-xs`, `.pop-in`). |
