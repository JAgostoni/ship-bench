## Assumptions made

1. **`docs/` and `.claude/` are excluded from Prettier.** The pre-existing spec documents aren't formatted to Prettier's Markdown style, and reformatting approved specs wasn't in scope; `prettier --check .` would otherwise fail on files this iteration doesn't own. `package-lock.json` and `next-env.d.ts` (generated files) are also excluded.
2. **No Google-font loading in the placeholder layout.** The scaffold's Geist font import was removed with the rest of the boilerplate; iteration 3 owns typography per the design spec. This also keeps offline builds working.
3. **drizzle-kit migration naming**: used `drizzle-kit generate --name init` so the file is `0000_init.sql` as the spec shows; the FTS SQL lives in `0001_fts.sql` (a separate `--custom` migration) rather than appended into `0000` — drizzle-kit's `--custom` flow creates a new journaled migration file, and the applied SQL is identical to architecture §11.
4. **Seed timestamps** are computed relative to "now" at seed time (fixed per-article day offsets, no randomness), so the home list's relative times look real whenever the seed is run.

## Issues encountered

- **Node version switch:** the machine had Node 22 active via nvm-windows; `nvm use 24.10.0` reported success but failed to recreate its `C:\nvm4w\nodejs` symlink (elevation), leaving no Node on PATH. Fixed by creating a directory junction (`mklink /J`) pointing at the installed v24.10.0 — junctions need no elevation. Node 24.10.0 is now active, matching the `engines` pin.
- **`create-next-app` into a non-empty repo:** scaffolded into a temp directory and moved files in, since the repo root contains `.claude/` which the CLI may reject. Scaffold-generated `AGENTS.md`/`CLAUDE.md`/`README.md` boilerplate was dropped.
- **Vitest 4 transform warning:** Vitest 4 uses oxc, not esbuild, for transforms; an initially-added `esbuild.jsx` option produced a warning and was removed (oxc defaults to the automatic JSX runtime).

## Decisions log

| # | Decision | Why |
| --- | --- | --- |
| 1 | FTS5 SQL in a second migration file (`0001_fts.sql`) instead of appended to `0000_init.sql` | This is what `drizzle-kit generate --custom` actually produces (the iteration task names that command); the journal tracks both and the applied schema is byte-for-byte the §11 SQL. |
| 2 | `client.ts` exports `getSqlite()` and `closeDb()` alongside `getDb()` | The smoke test (and later scripts/tests) need raw introspection and clean connection teardown; keeps tests off private internals. |
| 3 | `mkdirSync` of the DB directory inside the client | better-sqlite3 errors if the parent directory is missing; auto-creating `data/` makes a fresh clone + `db:seed` work even if `.gitkeep` is lost, and makes `data/kb-e2e.sqlite` work without extra setup. |
| 4 | Added `test-results/` to ignore files alongside `playwright-report/` | Playwright writes both; ignoring only one leaks artifacts into git/lint. |
| 5 | Seed checks emptiness with a `SELECT` of ids rather than relying on unique constraints | The schema has no natural unique key (titles may legitimately repeat); the brief's idempotency requirement is "only insert if empty", implemented literally. |
| 6 | `@types/node` bumped to `^24` (scaffold default was `^20`) | Matches the pinned Node 24 runtime. |
